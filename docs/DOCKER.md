## Первый запуск на Windows

1. Установите Docker Desktop по официальной инструкции:
   https://docs.docker.com/desktop/setup/install/windows-install/
2. Запустите Docker Desktop. Используйте Linux containers. Дождитесь готовности Docker Engine.
3. Откройте папку с Dockerfile и compose.yaml в VS Code.
4. В терминале (PowerShell или Git Bash) выполните:

    docker compose up -d --build --wait --wait-timeout 180

Открыть http://localhost:8080. При сборке нужен интернет для Node/Python-образов и зависимостей. Локальные Python, Node, .venv и npm для Docker-запуска не нужны.

Альтернатива: Terminal → Run Task → TaskQuest: Docker deploy. Есть также задачи просмотра логов и остановки.

## Что входит в конфигурацию

- Отдельный этап Node 22 собирает React из исходников и package-lock.json.
- Итоговый образ Python 3.12 содержит FastAPI и собранный интерфейс.
- Контейнер запускается непривилегированным пользователем.
- Healthcheck опрашивает /api/health.
- restart: unless-stopped перезапускает завершившийся контейнер. Это не включает Docker Desktop при входе в Windows автоматически; сам Docker Engine должен быть запущен.
- Именованный volume taskquest-ai_taskquest-data хранит /app/data/taskquest.db между пересборками и перезапусками.
- Рабочая папка не монтируется в контейнер: новая версия кода требует пересборки.
- Ключи, .env, локальная база, .venv и node_modules исключены из контекста сборки.
- .env опционален; без ключа работает локальный Sana Bot.

Необязательные переменные в .env рядом с compose.yaml:

    APP_PORT=8080
    OPENAI_API_KEY=
    OPENAI_MODEL=gpt-4o-mini

Контейнер всегда использует /app/data/taskquest.db. Локальный DATABASE_PATH на Windows не передаётся внутрь Linux-контейнера.

## Обновление кода с GitHub

Сначала убедитесь, что изменения сохранены:

    git status
    git pull --ff-only origin main

Если Git сообщает о конфликте или расхождении веток, не используйте reset --hard: сначала разберите изменения.

Затем обновите приложение:

    docker compose up -d --build --wait --wait-timeout 180
    docker compose ps
    docker compose logs --tail 100 app

Успешный результат: контейнер healthy, /api/health возвращает status ok, открывается каталог. Одного docker compose restart для обновления исходников недостаточно.

## Остановка и сохранность

Остановка без удаления данных:

    docker compose down

Повторный запуск:

    docker compose up -d --wait

Не используйте down -v, если хотите сохранить задачи, отклики и XP: этот флаг удаляет volume.

Первый запуск создаёт отдельную новую базу с демо-данными. Он не импортирует автоматически прежний backend/data/taskquest.db. Старую локальную базу конфигурация не меняет.

## Размещение на сервере

Сейчас порт привязан к 127.0.0.1 хоста. Это локальный Docker-деплой, а не публичная ссылка. Для размещения в интернете нужен выбранный сервер, HTTPS и контроль доступа: в приложении используются демо-роли, а не настоящая авторизация. Внешний сервер в текущем запросе пока не указан.
